# CHDS — CH Digital Services platform

Public website + CHDS AI Support (Groq) with persistent visitor identity and AI-to-human handoff, Human Support through Telegram, and a role-based admin dashboard (users, team, reports, revenue, analytics, security, audit, emergency control, backups, health). Hosted on Vercel, data in Supabase.

## Quick start
1. **Back up** your Supabase database, then run **all of `supabase.sql`** in Supabase → SQL Editor (existing installs: `supabase/migrations/002_platform_upgrade.sql` is the delta).
2. Set the variables from `.env.example` in Vercel (never commit real values).
3. Deploy (Framework: Other, no build command).
4. Open `/api/health`, then `/admin` → sign in (Telegram ID + password + Telegram code) → System Health → *Connect Telegram bot*, *Test AI*.
5. Team members: open the bot and press /start. Add team profiles in Team Management and staff accounts in User Management.

Full guide: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Structure
```
public/            website + dashboard (static). assets/: site.css/js, admin.css/js, admin-views*.js, icons.js, config.js (public settings only)
api/               9 Vercel functions: ai/[a], chat, human/[a], public/[a], admin/[a], telegram, stats, health, setup
lib/               server code (never served): core, validate, time, rbac, storage, notify, visitor, ai, support, handoff, rooms, bot, admin/*
supabase/migrations/ 001_original_schema.sql (unchanged), 002_platform_upgrade.sql (additive)
supabase.sql       001 + 002 (generated by `npm run build:sql`)
scripts/           check.mjs (static checks), dev-server.mjs (local Vercel-like server), build-sql.mjs
tests/             unit + integration tests (node:test), visual tests (Playwright), test double
docs/              architecture, deployment, security, features, backup & recovery, testing, upgrade notes
TEST_REPORT.md     what was executed, results, and what still needs live credentials
```

## Scripts
`npm run check` · `npm run check:env` · `npm test` · `npm run dev` (real env) · `node scripts/dev-server.mjs --fake` (test double) · `python3 tests/visual/run_visual.py` (with the fake server running) · `npm run build:sql`
