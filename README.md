# CHDS — CH Digital Services platform

Public website (with a live, published-only report feed) + CHDS AI Support (Groq, admin-managed knowledge base) with persistent visitor identity and AI-to-human handoff, Human Support through Telegram and the dashboard (strict case closure, priority, SLA, CSAT), a private team report portal with My Reports, and a role-based admin dashboard (users, team, reports & publication, revenue, analytics, notifications, security, audit, emergency control, backups, health). Hosted on Vercel, data in Supabase.

**V5 highlights:** strict, database-enforced *Close This Case* · private report portal (`/report-portal`) + My Reports · public report feed (`/reports`) · Telegram `/report` removed · Team Management Edit/Delete root causes fixed · AI Knowledge Base · Never-Ask-For-Password enforcement · notification center · Operations Analytics. See [docs/V5_GUIDE.md](docs/V5_GUIDE.md) and [docs/CASE_CLOSURE.md](docs/CASE_CLOSURE.md).

## Quick start
1. **Back up** your Supabase database. New installs: run **all of `supabase.sql`** in Supabase → SQL Editor. Existing installs: run only the migrations you have not applied yet — for V4 installs that is **`supabase/migrations/003_v5_cases_reports_kb.sql`** — *before* deploying the new code ([docs/MIGRATIONS.md](docs/MIGRATIONS.md)).
2. Set the variables from `.env.example` in Vercel (never commit real values).
3. Deploy (Framework: Other, no build command).
4. Open `/api/health`, then `/admin` → sign in (Telegram ID + password + Telegram code) → System Health → *Connect Telegram bot*, *Test AI*.
5. Team members: open the bot and press /start, then /portal for the private report portal link. Add team profiles in Team Management and staff accounts in User Management.

Full guide: [docs/DEPLOYMENT.md](docs/DEPLOYMENT.md).

## Structure
```
public/            website + dashboard (static). reports.html (public feed), report-portal.html (private, noindex). assets/: site.css/js, reports.js, portal.js, admin.css/js, admin-views*.js (incl. admin-views-v5.js), icons.js, config.js (public settings only)
api/               10 Vercel functions (Hobby limit 12): ai/[a], chat, human/[a], public/[a], portal/[a], admin/[a], telegram, stats, health, setup
lib/               server code (never served): core, validate, time, rbac, storage, notify, visitor, ai, knowledge, secrets, reports, reporters, cases, staffnotify, support, handoff, rooms, bot, admin/* (people, support, business, system, v5)
supabase/migrations/ 001_original_schema.sql (unchanged), 002_platform_upgrade.sql, 003_v5_cases_reports_kb.sql (both additive)
supabase.sql       001 + 002 + 003 (generated by `npm run build:sql`)
scripts/           check.mjs (static checks), dev-server.mjs (local Vercel-like server), build-sql.mjs
tests/             unit + integration tests (node:test: unit, api, admin, v5), visual + interaction tests (Playwright), test double
docs/              architecture, deployment, security, features, backup & recovery, testing, upgrade notes
TEST_REPORT.md     what was executed, results, and what still needs live credentials
```

## Scripts
`npm run check` · `npm run check:env` · `npm test` · `npm run dev` (real env) · `node scripts/dev-server.mjs --fake` (test double) · `python3 tests/visual/run_visual.py` (with the fake server running) · `npm run build:sql`
